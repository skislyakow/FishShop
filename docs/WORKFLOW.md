# Как работать на двух машинах

Проект ведётся на двух машинах. Код и схема ходят через **git-репозиторий**, данные Strapi —
через **архивы** (`docs/DB-SYNC.md`). Ниже — правила, чтобы две машины не разошлись.

## Главное правило

> **Код синхронизируем git-ом, данные — архивами. Никогда наоборот.**

Не коммить `.tmp/data.db`, не копируй файлы схем руками, не передавай `.env`.

## Что коммитим, а что нет

| Коммитим | Не коммитим |
| --- | --- |
| `cms/src/`, `cms/config/`, `cms/package.json`, `cms/package-lock.json` | `cms/.env` |
| `docs/`, `AGENTS.md`, `GLOSSARY.md`, `README.md` | `cms/.tmp/` (в т.ч. `data.db`) |
| `skills-lock.json`, `scripts/`, корневой `package.json` | `.agents/skills/` (личный инструмент, ставится из lockfile) |
| `cms/.env.example` | `cms/node_modules/`, `cms/.cache/`, `cms/build/` |
| `bot/pyproject.toml`, `bot/uv.lock` (когда появится бот) | `backups/`, `bot/.venv/` |

## Ветки и коммиты

- Ветка на задачу: `t<номер>-<краткий-слаг>`, например `t3-content-types`.
- `main` не переписываем. Работаем через ветку и PR (даже для соло-проекта это страховка).
- Коммиты атомарные, в формате Conventional Commits:
  - `feat(cms): add fish content-type`
  - `fix(cms): allow anonymous read on published fish`
  - `docs: describe db sync ritual`
  - `chore: bump strapi`
- В одном коммите — одна мысль. Смешанные коммиты дороже разбирать при конфликтах.

## Ритуал начала и конца сессии

**Начало работы на машине:**

```bash
git pull --rebase            # подтянуть чужие изменения
cd cms && npm ci             # если менялся package-lock.json
npm run develop              # Strapi: применит новые content-types к своей SQLite
```

Если с другой машины передали архив данных — импортировать его до начала работы
(`docs/DB-SYNC.md`).

**Конец работы:**

```bash
git add -A
git commit -m "feat(cms): ..."
git pull --rebase            # на случай, если вторая машина уже что-то запушила
git push
```

Если правились данные (товары, заказы) и они нужны второй машине — сделать `npm run db:export`
и передать архив.

## Конфликты

- **Обычные файлы** — правим руками, коммитим.
- **`cms/package-lock.json`** — не мержим построчно: принять одну сторону и перегенерировать
  через `npm install`, затем закоммитить.
- **Схема content-type** (`schema.json`) — при одновременном редактировании одного типа будут
  конфликты. Чтобы их не было: меняем модель данных по очереди и сразу пушим.

## Секреты

- `cms/.env` создаётся на каждой машине из `cms/.env.example` (`docs/SETUP.md`).
- Ключи приложений генерируются **заново** на каждой машине — у двух инстансов Strapi они разные.
- Если секрет всё же утёк в git — не переписывай историю в одиночку, сообщи и смени ключ.

## Синхронизация настроек окружения

Обе машины должны держать одинаковые версии:

- Node.js — из `.nvmrc`/`engines` (Node 20–26).
- Зависимости — по закоммиченным lock-файлам: `cms/package-lock.json` (npm), `bot/uv.lock` (uv).
- Окружение целиком — одной командой: `npm run setup` (skills из `skills-lock.json` + `npm ci`
  в `cms/`; для бота — `uv sync`). На сервере: `npm run setup:prod`.
