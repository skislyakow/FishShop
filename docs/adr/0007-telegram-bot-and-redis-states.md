# Python + python-telegram-bot 22 и состояния диалога в Redis

Для Telegram-бота выбран Python-фреймворк **python-telegram-bot** (версия 22) и отдельное
хранилище состояний диалога — **Redis**. Python уже используется в проекте для REST-клиента
Strapi (`bot/`, управление зависимостями через `uv`), поэтому новых языков не появляется.

Стейт-машина — центральная механика бота: состояние диалога обслуживает своя функция, а текущее
состояние пользователя лежит в Redis под ключом `state:<chat_id>`. Это нужно не ради красоты
кода: Денису важно понимать, где человек остановился — «отказался в меню, потому что не
понравился ассортимент» и «остался в корзине, потому что не устроила цена» на уровне логов
выглядят одинаково, если не знать текущее состояние. Хранилище вне процесса также переживает
перезапуск бота и позволяет запускать несколько экземпляров.

## Рассмотренные варианты

- **python-telegram-bot 13.15** — версия из гиста урока. Отклонена: релиз 2021 года, синхронный
  API, а его зависимость `tornado==6.1` не имеет колёс под Python 3.12 и собиралась бы из
  исходников (на Windows это означает зависимость от MSVC).
- **aiogram 3** — современная альтернатива, но материал урока написан под python-telegram-bot,
  и следующие шаги пришлось бы переносить вручную.
- **Состояния в памяти процесса** — проще всего, но теряются при рестарте и не работают с
  несколькими экземплярами.
- **Состояния в Strapi** — противоречит границе ответственности: состояние диалога пользователя
  не является данными магазина и не должно попадать в content-types.
- **python-telegram-bot 22 + Redis** — выбран: актуальная версия с async-API, ставится без сборок
  (зависимости — только `httpx`), а Redis доступен в WSL на целевых машинах.

## Последствия

- Код бота асинхронный (`async def`-хэндлеры), в отличие от синхронного гиста урока — логика
  стейт-машины при этом не меняется.
- На каждой машине нужен запущенный Redis. В WSL Ubuntu он установлен и включён как сервис
  (`systemctl is-enabled redis-server` → `enabled`), слушает `127.0.0.1:6379` без пароля, а WSL2
  пробрасывает порт на Windows. Добавлено в чек-лист `docs/SETUP.md`.
- Состояния накапливаются без TTL: чистка — вручную (`DEL state:<chat_id>`), либо добавим TTL,
  когда накопится практика.
- Имена переменных окружения — `REDIS_*`, а не `DATABASE_*` как в гисте: не пересекаются
  со Strapi, у которого `DATABASE_*` заняты под БД.
