# План работ

Тикеты по уроку. Формат — «трассирующие пули»: каждый тикет даёт работающий срез, который можно
проверить. Зависимости указаны стрелками `←`.

Легенда статусов: `[ ]` — не начат, `[~]` — в работе, `[x]` — готов.

## Этап 1. Strapi-магазин (критерий урока)

- [x] **T0. Репозиторий и документация.**
  git init, `.gitignore`, доки. Проверка: репозиторий открывается, доки на месте.

- [x] **T1. Каркас Strapi-проекта.**
  `cms/` создан, зависимости ставятся бутстрапом, `npm run develop` поднимает админку.
  Проверка: админка на <http://localhost:1337/admin> создаёт администратора.

- [x] **T1b. Бутстрап окружения.** ← T1
  `scripts/bootstrap.mjs` + `npm run setup`: skills из `skills-lock.json`, `npm ci` в `cms/`,
  `uv sync` для будущего `bot/`. Проверка: на чистой машине `npm run setup` идемпотентен,
  `.agents/skills/` в `.gitignore`.

- [ ] **T2. Модель данных магазина.** ← T1
  Создать content-types: `Category`, `Fish` (+ `draftAndPublish`), `Customer`, `Order`,
  `OrderItem` с relations. Проверка: типы видны в Content Manager, поля совпадают с
  `docs/ARCHITECTURE.md`.

- [ ] **T3. Витрина.** ← T2
  Наполнить каталог: 2–3 раздела, 5–8 товаров с ценой за кг и фото. Проверка: товары
  опубликованы и видны в админке.

- [ ] **T4. Доступ по API.** ← T2
  Настроить публичные права чтения на `Fish`/`Category` и создать API-токены. Проверка:
  `GET /api/fishes?populate=*` возвращает опубликованные товары.

- [ ] **T5. Синхронизация БД.** ← T1
  Добавить скрипты `db:export` / `db:import`, описать ритуал передачи. Проверка: экспорт с
  одной машины импортируется на другой, каталог совпадает.

## Как вести тикеты

- Крупные задачи — в GitHub Issues, метки triage: `needs-triage`, `needs-info`,
  `ready-for-agent`, `ready-for-human`, `wontfix` (см. `docs/agents/`).
- Ветка на тикет: `t<номер>-<слаг>`.
- Готово = проверка из тикета проходит на обеих машинах.
