# Корзина в Strapi, ключ — Telegram ID

Готовой корзины в Strapi нет, поэтому она заведена своими content-types: `api::cart.cart` и
`api::cart-item.cart-item`. Корзина привязана к покупателю текстовым полем
`telegram_user_id` (обязательное, уникальное), позиция корзины ссылается на `fish` и хранит
количество в килограммах (`quantity_kg`, float). Draft & Publish у обоих типов выключен.

## Контекст

Покупатель приходит в бот из Telegram и опознаётся по `telegram_user_id`; email и пароля у
него нет. Связка «корзина → позиции → товар» нужна, чтобы на T8 превратить набранное в
`Order`/`OrderItem` с зафиксированной ценой.

## Рассмотренные варианты

- **Корзина в Redis (`cart:<chat_id>`)** — проще коду бота, но корзина — это данные магазина,
  а не состояние диалога: ADR-0007 проводит границу именно так. Плюс корзина терялась бы при
  ручной чистке состояний (`DEL state:<chat_id>`) и не была бы видна в админке.
- **Relation с `users-permissions.user`** (вариант из задания) — покупателю пришлось бы
  заводить email и пароль, а в Strapi 5 Content-Type Builder не предлагает плагинные типы
  в качестве целей relation. Опознание всё равно шло бы по Telegram ID.
- **Отдельная модель `Customer` (`api::customer.customer`)** — правильная форма, но имя и
  телефон появляются только при оформлении заказа, то есть на T8. Заводить её сейчас значило
  бы держать два источника идентичности (`Cart.telegram_user_id` и `Customer`).
- **Поле `telegram_user_id` в корзине** — выбрано: это ровно та альтернатива, которую урок
  разрешает («вместо создания пользователя проще добавить текстовое поле»), и она совпадает с
  тем, что бот умеет уже сейчас.

## Последствия

- Бот ищет корзину по `telegram_user_id`, а не создаёт новую при каждом входе. Уникальность
  проверяет Strapi при записи; уникального индекса в SQLite нет — Strapi 5 их не создаёт
  (проверено и на `up_users.username`). Значит дубли можно залить только в обход API, через
  SQL или `db:import`.
- `draftAndPublish` выключен у `Cart` и `CartItem`. С включённым D&P записи создавались
  черновиками и не отдавались по API, а `unique` проверялся только при публикации. При
  выключении D&P Strapi удаляет черновики — это надо помнить перед сменой режима на данных,
  которые нужны.
- Цена в корзине не хранится: она берётся из товара, а фиксируется только в позиции заказа
  (см. «Позиция заказа» в `GLOSSARY.md`).
- Каталог по-прежнему состоит только из `Fish`: корзина — рабочая таблица, в витрину бота она
  не попадает.
- После выключения D&P в таблицах осталась колонка `published_at`: Strapi не удаляет колонки
  автоматически. На поведение она не влияет.
- Заказ (T8) создаётся из корзины: контакт спрашивается у покупателя, `Customer` заводится
  там же, а `quantity_kg` превращается в `quantityKg` позиции заказа.
