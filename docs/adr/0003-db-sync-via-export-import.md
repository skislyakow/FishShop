# Синхронизация данных между машинами через strapi export/import

Две машины правят одну и ту же витрину, но у каждой своя SQLite. Данные (записи + медиа)
переносим вручную архивами `strapi export` / `strapi import`, а не через общую БД и не через
SQLite-файл в git. Модель — «одна БД, один писатель»: данные в каждый момент правит одна машина,
затем отдаёт архив второй.

## Рассмотренные варианты

- **Общая удалённая БД (Postgres)** — один источник правды в реальном времени, но добавляет
  внешний сервис, сеть и общий `DATABASE_URL`; избыточно для учебного проекта. Кандидат на прод.
- **SQLite в git / git-lfs** — бинарные конфликты, риск утечки секретов, раздувание истории.
- **`strapi export` / `import`** — выбран: официальный механизм, переносит записи, связи, схемы,
  конфиг и медиа одним архивом.

## Последствия

- `strapi import` удаляет текущие данные — обязателен ритуал «выгрузил → передал → импортировал».
- Архив передаётся вне git (`backups/` в `.gitignore`).
- Схемы на обеих машинах обязаны совпадать; сначала `git pull` и старт Strapi, потом импорт.
- Админ-аккаунты и API-токены не переносятся, создаются на каждой машине.
